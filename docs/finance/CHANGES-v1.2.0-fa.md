# «آتیران مالی» ۱.۲.۰ — بخش «بررسی سلامت و بارگذاری» در شروع برنامه

این نسخه همان چیزی است که خواستید: **در همان اول، یک صفحهٔ لودینگ جذاب که سلامت سیستم را بررسی و اطلاعات را آماده می‌کند** — و در همان حال، صفحهٔ ورود هم بازسازی شده تا فرم ورود همیشه روی صفحه باشد.

## ۱) صفحهٔ شروع: «بررسی سلامت و بارگذاری»

هفت بررسی واقعی، پشت سر هم و روی همان صفحه، با **درصد پیشرفت**، **زمان هر گام** و **نتیجهٔ هر گام**:

| بررسی | چه چیزی تأیید می‌شود |
|---|---|
| آماده‌سازی رابط کاربری | پوسته، قلم وزیرمتن و ابزارهای رابط ساخته شده‌اند |
| اینترنت گوشی | شبکهٔ فعال واقعی (وای‌فای/داده همراه) با دسترسی اینترنت |
| یافتن نام سرور (DNS) | نام سرور به آدرس IP تبدیل می‌شود (با زمان) |
| پورت سرور ۱۴۳۳ | پورت SQL از شبکهٔ گوشی باز است (با زمان) |
| ورود به SQL Server | ورود برنامه با jtds روی پایگاه برقرار می‌شود |
| پایگاه داده و تاریخ سرور | `DB_NAME()` و تاریخ جلالی خود سرور پاسخ می‌دهند |
| جدول‌های مالی (نمونه‌خوانی) | sailfact، dar، getchk، cust_act و BANK واقعاً خوانده می‌شوند |

* هر خط از «○» به «…» و بعد «✓ سبز» تغییر می‌کند و زمان آن (میلی‌ثانیه) کنارش نوشته می‌شود.
* خطای هر گام با **نوع و متن دقیق خطا** و رنگ قرمز روی همان خط می‌آید؛ بررسی متوقف می‌شود و دکمه‌های «تلاش دوباره»، «بررسی اتصال به سرور» و «ورود با فرم ساده» ظاهر می‌شوند.
* اگر بررسی بیش از ۱۰ ثانیه طول بکشد، دکمه‌های «ورود با فرم ساده» و «بررسی اتصال» خودشان ظاهر می‌شوند تا هیچ‌وقت منتظر نمانید.
* وقتی همه‌چیز سالم است پیام «همه‌چیز سالم است — اطلاعات آمادهٔ نمایش است» می‌آید و با «ورود به برنامه» به صفحهٔ ورود (یا مستقیم به میزکار، اگر نشست فعال باشد) می‌روید.

## ۲) صفحهٔ ورود بازسازی شد (فرم همیشه روی صفحه)

در نسخهٔ قبل، بین سربرگ و کارت ورود یک فضای خالی بزرگ دیده می‌شد و فرم ورود بیرون از صفحه می‌ماند. اکنون:

* فرم **بلافاصله زیر سربرگ** قرار می‌گیرد (لوگو ۷۴dp، بدون ردیف قرص‌های اضافی، بدون فاصله‌گذار کشسانی).
* `ScrollView` با `fillViewport=false` ساخته می‌شود؛ یعنی محتوا هرگز کشیده/پخش نمی‌شود.
* یک **محافظ چیدمان** اضافه شد: اگر روی دستگاهی کارت ورود بیرون از پنجره بیفتد، برنامه خودش صفحه را تا کارت اسکرول می‌کند.
* جعبهٔ فیلدها ۵۰dp شد و توضیح «نمایش رمز» روشن‌تر نوشته شد؛ دکمهٔ اصلی «ورود به آتیران مالی» و زیر آن «بررسی اتصال به سرور».

## ۳) پنل ساده و ایمن (پشتیبان)

پنل متنی ساده‌ای که در ۱.۱.۱ اضافه شد سر جایش است، ولی حالا **پنهان** است مگر لازم شود: اگر ساخت رابط گرافیکی روی گوشی ممکن نشود یا خودتان «ورود با فرم ساده» را بزنید، همان پنل با فرم ورود ساده و گزارش راه‌اندازی می‌آید. گزارش فنی (مرحله‌ها و خطای اجرای قبلی) فقط در همان حالت نشان داده می‌شود.

## ۴) نسخه

`versionCode 4` · `versionName 1.2.0` — با کلید ثابت پروژه امضا می‌شود و روی ۱.۱.۱ نصب می‌شود (بدون پاک شدن داده).

# ۱.۲.۱ — «برنامه بعد از ورود بسته می‌شد»

گزارش: «پس از ورود نام کاربری و کلمه عبور، با اینکه اتصال را سالم تشخیص می‌دهد، برنامه بسته می‌شود.»

## علت

بررسی سلامت (اینترنت → DNS → پورت → ورود SQL → تاریخ سرور) روی یک ترد پس‌زمینه انجام می‌شود و سالم بود؛
اما **نمایش داده‌ها روی ترد اصلی** انجام می‌شود. هر خطایی که هنگام چیدن صفحهٔ میزکار (کشیدن نمودار، ساخت
کارت‌ها، خواندن کلیدهای JSON) رخ بدهد، پیش از این «بی‌صدا و بدون هیچ پیامی» کل برنامه را می‌بست — و همین
اتفاق بعد از ورود می‌افتاد.

## اصلاح

* **همهٔ فراخوانی‌های رابط کاربری محافظت شدند:** `FinDb.deliver` (مسیر مشترک همهٔ صفحه‌ها)، بررسی سلامت،
  ادامهٔ ورود، باز کردن صفحه‌ها و تب‌ها، ساخت تأخیری هر صفحه و دکمهٔ «تلاش دوباره».
* هر خطای نمایش به `reportUiError` می‌رود: در گزارش برنامه ثبت می‌شود و به‌جای بسته شدن برنامه، **کارت خطا با
  کد رویداد و دکمهٔ «تلاش دوباره»** نشان داده می‌شود.
* **گزارش خطای اجرای قبلی روی صفحهٔ اول:** اگر اجرای قبلی کامل نشده باشد، بالای صفحهٔ «بررسی سلامت و
  بارگذاری» یک کارت قرمز با متن دقیق خطا ظاهر می‌شود تا همان را برای پشتیبانی بفرستید.

## نسخه

`versionCode 5` · `versionName 1.2.1`
