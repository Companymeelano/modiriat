# گزارش بازبینی MEELANO — ۱۴۰۵/۰۷/۱۳ (۲۰۲۶-۱۰-۰۵)

## دامنه و محدودیت

- بازبینی ایستای کد Android، manifestها، workflow ساخت و تصاویر موجود در `docs/screenshots/`؛ شامل نمونه‌های ورود، خانه، سبد، فروشگاه، کارکنان، مدیریت، تم روشن/تیره، نمایش باریک و تبلت.
- تصاویر از اجرای قبلی‌اند و آزمون زندهٔ همین تغییرات نیستند. این محیط Java، Android SDK و Gradle نصب‌شده ندارد؛ بنابراین کامپایل، آزمون JUnit، Android Lint و آزمون روی دستگاه برای تغییرات این شاخه هنوز تأیید نشده‌اند.
- XML manifest/rules، دستورهای shell و `git diff --check` به‌صورت محلی بررسی شده‌اند.

## تغییراتی که در این شاخه اعمال شده‌اند

1. **Pool اتصال SQL** — `MeelanoConnectionLease` هر اجاره را فقط یک‌بار آزاد می‌کند و استفاده پس از `close()` را رد می‌کند. اعتبارسنجی اتصال از قفل سراسری بیرون رفته، pool generation اتصال‌های متعلق به تنظیمات/شبکهٔ قدیمی را از بازاستفاده منع می‌کند و خطای socket باعث کنارگذاشتن کل نسل pool می‌شود. آزمون واحد برای lease و بررسی پرانتز SQL اضافه شده؛ هنوز اجرا نشده است.
2. **حریم خصوصی شبکه** — مسیر قبلی می‌توانست کل process را از VPN خارج کند (`bindProcessToNetwork`). اکنون برنامه فقط وضعیت VPN را برای پیام عیب‌یابی می‌خواند و مسیریابی را به Android و انتخاب کاربر واگذار می‌کند.
3. **دسترس‌پذیری لمس** — نمودار و دو امضای سفارشی `performClick()`، رخداد پایان لمس و توضیح متن‌خوان دارند؛ انتخاب نقطهٔ نمودار برای TalkBack اعلام می‌شود. برای listener بازخورد بصری، suppress محدود با توضیح علت افزوده شده است.
4. **درستی locale** — تبدیل‌های متنی حساس به locale به `Locale.ROOT` تغییر کرده‌اند.
5. **Manifest** — قوانین استخراج دادهٔ پشتیبان، برای cloud backup و انتقال دستگاه، صریح شده‌اند. مجوزهای استفاده‌نشدهٔ میکروفون و اثرانگشت حذف شده‌اند.
6. **ابزار ساخت** — `gradlew` اجرایی و نسخهٔ fallback آن با Gradle 8.11.1 workflow هم‌تراز شده است. workflow ورودی دستی `version_name` با اعتبارسنجی `x.y.z` دارد؛ `versionCode` همچنان افزایشی است. حالت دستی `validation_only` هم اضافه شده تا تست/تحلیل/اسکرین‌شات بدون امضا یا انتشار APK release اجرا شود.

## یافته‌های امنیتی که پیش از انتشار تازه باید تعیین‌تکلیف شوند

### بحرانی — کلید امضای release در مخزن عمومی افشا شده است

- مخزن GitHub عمومی است و `MEELANO-Android/app/signing/meelano-install.p12` در Git track می‌شود؛ تنظیم امضای release نیز در `app/build.gradle` اطلاعات ثابت این keystore را دارد.
- گواهی داخل APK ثبت‌شدهٔ `apk/MEELANO-v6.2.66-release.apk` با گواهی همین keystore تطبیق داده شد. پس کلید فعلی برای امضای نسخه‌های آینده محرمانه نیست.
- **کلید را خودسرانه عوض نکردم**: تغییر گواهی می‌تواند نصب به‌روزرسانی روی نسخه‌های نصب‌شده را متوقف کند. پیش از release تازه، مالک محصول باید مسیر چرخش امضا/سازگاری نصب‌های موجود را طراحی کند، کلید جدید را فقط در GitHub Secrets نگه دارد و buildهای رسمی را به آن منتقل کند. تا آن زمان هر APK تازه با کلید موجود قابل جعل است.

### بحرانی — ورود مدیریتی و دسترسی کامل در کلاینت پیاده‌سازی شده‌اند

`MainActivity.authenticateBackOffice()` زوج‌های مدیریتی را محلی می‌پذیرد و نشست با تمام مجوزها می‌سازد؛ کنترل سمت سرور انجام نمی‌شود. مقادیر صرفاً مبهم‌سازی شده‌اند و از APK قابل استخراج‌اند. این منطق باید حذف شود؛ API سمت سرور باید احراز هویت، مجوز هر درخواست و ثبت رویداد را اعمال کند. اعتبارنامه‌های مدیریتیِ تعبیه‌شده نیز باید پس از مهاجرت چرخانده شوند.

### بحرانی — برنامهٔ موبایل مستقیماً به SQL Server متصل است

میزبان، نام کاربری و گذرواژهٔ دیتابیس در کلاینت (هرچند obfuscate شده‌اند) مصرف می‌شوند و درخواست‌ها از `jTDS 1.3.1` می‌گذرند. همین اطلاعات از APK قابل بازیابی‌اند؛ نصب چند flavor یا بررسی مجوز در UI مرز امنیتی محسوب نمی‌شود. هدف نهایی باید API میانی با هویت محدود، rate limiting، authorization سمت سرور و حذف دسترسی مستقیم اینترنتی SQL Server باشد.

### بالا — رمزنگاری و ترافیک cleartext

`network_security_config.xml` به‌طور سراسری `cleartextTrafficPermitted="true"` دارد و بخشی از قابلیت‌های آدرس‌پذیر کاربر (از جمله دستگاه‌های دزدگیر) URL با `http://` می‌سازند. URL اتصال jTDS نیز الزام TLS را تعیین نمی‌کند. Android Lint علاوه بر این، دو مورد `TrustAllX509TrustManager` را در خود dependency قدیمی jTDS گزارش کرده است؛ فعال‌بودن دقیق آن‌ها به تنظیم TLS ران‌تایم وابسته است و باید با سرور واقعی بررسی شود. راه درست: API با HTTPS معتبر، الزام TLS برای ارتباط‌های دیتابیس تا زمان حذف آن‌ها، و محدودسازی مقصدها؛ صرفاً تغییر سراسری cleartext بدون مهاجرت، قابلیت HTTP موجود را می‌شکند.

## بازبینی رابط و تجربهٔ کاربر

- **نقاط قوت قابل مشاهده در تصاویر:** هویت بصری نقش‌محور، تم‌های هماهنگ روشن/تیره، زبان RTL، اجزای کارت/دکمهٔ منسجم، ناوبری پایین و CTA روشن در سبد فروش. تصاویر فروشگاه، کارکنان و ویزیتور مسیرهای کلیدی را نشان می‌دهند.
- **مسئلهٔ مشاهده‌شده:** تصویر داشبورد مدیر هنگام قطع ارتباط، پس از یک کارت خطا، فضای خالی بزرگی دارد و اطلاعات جایگزین ندارد. پیشنهاد: cache آخرین آمار با زمان آخرین به‌روزرسانی، skeleton/empty state معنادار و راهنمای اتصال؛ نه صرفاً نمایش فضای خالی.
- **نیازمند آزمون واقعی:** نسبت کنتراست رنگ‌های کم‌رنگ در پالت روشن با اندازه‌گیری WCAG؛ بزرگ‌نمایی متن سیستم، TalkBack، اندازه‌های باریک و تبلت، حالت landscape و استفاده با یک دست. تصاویر فعلی برای ادعای دسترس‌پذیری کامل کافی نیستند.
- `MainActivity.java` حدود ۲۸٬۹۵۳ خط است و چند flavor/دامنه را در یک Activity جمع کرده است. برای نگهداری حرفه‌ای، جداسازی navigation/UI، دامنهٔ فروش و احراز هویت به ماژول‌های مستقل و تست‌پذیر لازم است.
- Manifest هنوز Activity را portrait قفل می‌کند؛ برای تبلت/تاشو باید پشتیبانی landscape و layout تطبیقی ارزیابی شود.

## کیفیت و CI

- workflow آزمون‌های `Store` و `Tax` را اجرا می‌کند، اما `javac`، Lint و PMD در حال حاضر با `|| true` خطاها را غیرمسدودکننده می‌کنند؛ محافظت build سبز به معنی پاک‌بودن این تحلیل‌ها نیست.
- گزارش‌های فعلی `docs/analysis/` پیش از تغییرات این شاخه تولید شده‌اند و باید در CI دوباره تولید شوند.
- تغییرات این شاخه هنوز build/test تأییدشده ندارند؛ APK موجود پایین‌تر **نسخهٔ ساخته‌شده از این تغییرات نیست**.

[دانلود MEELANO-v6.0.1-release.apk — GitHub Release build 120](https://github.com/Companymeelano/modiriat/releases/download/v6.0.1-build-120/MEELANO-v6.0.1-release.apk)

**هشدار:** این لینک متعلق به نسخهٔ قبلی است و اصلاحات همین شاخه را شامل نمی‌شود. ساخت release جدید از همین شاخه را تا تعیین تکلیف کلید امضای افشاشده و اجرای CI، تأییدشده تلقی نکنید.

## پیشنهاد ترتیب اقدام بعدی

1. فوراً ورود محلی مدیریتی را متوقف و دسترسی مستقیم دیتابیس/اعتبارنامه‌ها را به API سمت سرور منتقل کنید؛ credentialهای افشاشده را rotate کنید.
2. برنامهٔ مهاجرت امضای Android را با توجه به نصب‌های موجود تعیین کنید؛ کلید جدید را خارج از Git نگه دارید و انتشار را به آن مشروط کنید.
3. VPN bypass را با آزمون شبکه تأیید کنید؛ برای API و SQL TLS و دامنه‌های مجاز را اعمال کنید.
4. سپس CI کامل را اجرا کنید: testهای همهٔ flavorها، assemble release، `apksigner verify`, تحلیل‌های مسدودکننده، و تست روی Android 13–16/تبلت/TalkBack.
5. در آخر: اندازه‌گیری contrast، تست font scale و offline UX، و بازطراحی dashboard disconnected.
